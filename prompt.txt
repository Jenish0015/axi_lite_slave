## Register map

| Address | Name      | Access | Description |
|---------|-----------|--------|-------------|
| 0x00    | CTRL      | Write (per-byte WSTRB) | **Byte 0:** if `WSTRB[0]=1` and `WDATA[0]=1`, **start** pipeline from current **DATA_IN**; if `WSTRB[0]=1` and `WDATA[0]=0`, **clear** pipeline. If `WSTRB[0]=0`, **no** start/clear (masked write). Other bytes: update CTRL storage per strobes if you implement read-back. |
| 0x04    | DATA_IN   | Write (per-byte WSTRB) | Merge `WDATA` into `DATA_IN` only on strobed bytes; others keep previous value. |
| 0x08    | DATA_OUT  | Read | While pipeline **busy**, return **0**. After run completes, return the **pipelined** result (see below). |
| 0x0C    | STATUS    | Read | **0** when idle/busy without completion bit set; **bit 0 = 1** when a run has **finished** (golden behavior). |

Hidden cocotb tests read **CTRL** after reset (expect **0**); implement read-back consistently if you expose CTRL on reads.

---

## Pipeline and arithmetic

- **`PIPE_CYCLES` = 32**: From **start** until **DATA_OUT** and **STATUS** reflect completion, **32 enabled clock edges** must elapse (see backpressure: cycles where the slave stalls on **R** or **B** must **not** count down).
- **Operand**: When a start is recognized, latch from the current **DATA_IN** register (post-merge).
- **Result** (32-bit wrap on XOR/add, then shift):

  `result = (((operand ^ 32'hA5A5A5A5) + operand) >> 2`

- **While busy**: **DATA_OUT** reads must be **0** (early-read checks).
- **Stall**: Typical `pipe_stall = (RVALID & ~RREADY) | (BVALID & ~BREADY)`; do not advance the pipeline counter while stalled.

---

## CTRL / reset

- **Clear** stops the pipeline and clears busy/done behavior per your FSM (golden clears STATUS on trigger and sets done at end).
- **ARESETn** low: cancel in-flight work; after release, **DATA_OUT**, **STATUS**, and **CTRL** read as **0** where tested; no stale completion from before reset.

---

## AXI4-Lite (strict)

1. **AW** and **W** decoupled (either order).
2. **BVALID** only after **both** AW and W handshakes for that transaction.
3. **RVALID** after AR handshake; **RDATA/RRESP** stable until **RREADY** completes.
4. **RREADY=0**: hold **RVALID** and data/resp for multiple cycles.
5. **BREADY=0**: hold **BVALID/BRESP**; keep **AWREADY=0** while a write response is pending (tested).
6. Partial **WSTRB** on **DATA_IN** required for byte-wise merge.

**Responses:** Hidden tests expect **OKAY** (`2'b00`) on successful mapped accesses. SLVERR on unmapped or illegal writes is **not** asserted by the hidden suite (your local TB may add it).

---

## Reference FSM shape (golden-style)

- **Write:** small FSM—capture **AW**, then accept **W**, then assert **BVALID** until **BREADY**. Only apply register writes on the **W** handshake using the latched address. **AWREADY** must respect pending **B**.
- **Read:** after **AR**, assert **RVALID** and hold until **RREADY**; **ARREADY** low while a read response is pending.

---

## Datapath (must match timing, not combinational)

- Do **not** update **DATA_OUT** with the final result on the same cycle as the CTRL start. Commit **DATA_OUT** (and set **STATUS** done) only after the **fixed delay** (32 non-stalled cycles) from start.
- **STATUS[0]** should reflect **done** after that delay; clearing via CTRL (byte0 strobe with 0) should align with golden expectations.

## Common pitfalls (hidden tests)

- Masked **CTRL** with **`WSTRB[0]=0`** must not start or clear the pipeline.
- Backpressure must **freeze** the pipeline counter.
- **DATA_IN** built from multiple partial writes must match **byte-wise** merge before trigger.
- **Reset** mid-flight must cancel pending results.

<HINTS>
 - Implement AXI writes with a simple 3-state FSM: capture AW first, then accept W, then hold BVALID until BREADY.

 - For reads, keep RVALID/RDATA stable while RREADY is low, and only accept a new AR when no read response is pending.

 - Only CTRL (0x00) and DATA_IN (0x04) are writable; writes to DATA_OUT/STATUS or unmapped addresses should return SLVERR.

 - Treat CTRL[0] as a level with edge detection: start a new run only on a 0→1 transition; while CTRL[0] stays 1, further writes of 1 must not restart. Clearing CTRL[0] (when byte0 is strobed) should clear the done flag.

 - When a trigger edge is recognized, latch the operand from the current DATA_IN register (after any WSTRB merge for that register)—do not sample a free-running bus—and delay committing DATA_OUT/STATUS until the full fixed-cycle pipeline finishes.

 - On writes, merge WDATA into each target register only on bytes where WSTRB is 1; other byte lanes of that register retain their previous values (for both CTRL and DATA_IN).

 - Asserting ARESETn low should clear user-visible registers and cancel any in-progress pipeline so DATA_OUT/STATUS do not reflect a pre-reset run after release.

 - While a write response (BVALID) is pending, keep AWREADY low until B completes; while a read response (RVALID) is pending, keep ARREADY low until R completes.

 - AW and W are independent: the master may assert W before AW or AW before W. Buffer both the latched address and the latched WDATA/WSTRB, and only emit B after both handshakes for that transaction—do not assume AW always arrives first.

 - If a new CTRL start (0→1 on byte0) occurs while an earlier run is still in progress, the spec expects the new run to take over: refresh the latched operand and restart the fixed-cycle countdown so the final DATA_OUT reflects the latest operand, rather than ignoring the trigger because the pipeline is already busy.

 - Read channel is usually modeled with **registered** outputs: after `RVALID && RREADY` completes, `RVALID` drops and **`ARREADY` returns to 1 on the next `posedge`**, not as a combinational fix-up in the same cycle. Hidden checks sample `ARREADY` on that following edge (see golden-style read FSM).

 - If you write an **Icarus** testbench: after `ARVALID && ARREADY` (or AW/W handshakes), wait **at least one `posedge` before** deasserting `ARVALID`/`AWVALID`/`WVALID`; dropping VALID in the same simulation time step as the handshake often makes `RVALID`/`BVALID` never appear in the sampled schedule.

 - Golden `DATA_OUT` matches **32-bit wrapping** add before `>> 2`: `tmp = (operand ^ 32'hA5A5A5A5) + operand` with unsigned overflow, then `tmp >> 2`. Cross-check expected values in Python with `(tmp & 0xFFFFFFFF) >> 2`—hand-calculated sums that omit wrap will disagree with cocotb.

 - **Supersede while busy:** a CTRL write with `WSTRB[0]=1` and `WDATA[0]=1` while **`ctrl_reg[0]` is already 1 and the pipeline is still active** should **reload** the operand from the current `data_in_reg` and **reset** the delay counter (latest operand wins). That is separate from the rule that writes of 1 while CTRL stays high **without** a new busy-phase trigger must not start an extra run after the previous one has **finished**.
